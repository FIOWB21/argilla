# Виправлення гарячих клавіш у Argilla

Привіт! Підготував патч для проблеми з клавішами `1/2/3`: після кліку по фону або тексту вони переставали вибирати відповіді, доки знову не натиснеш на один із варіантів.

Тепер цифри працюють і після звичайного, подвійного та потрійного кліку по тексту. Патч змінює чотири компоненти інтерфейсу; логіку збереження, переходів між записами та бекенд я не чіпав.

Додаю [annotation-shortcuts-v2.8.0.patch](./patches/annotation-shortcuts-v2.8.0.patch). Він містить усі зміни виправлення. Перевірив його застосування до чистої **Argilla 2.8.0** (`78cb5183`). Наша робоча збірка може відрізнятися, тому спочатку треба звірити зміни з нею.

Локально я перевірив роботу на тестовому стенді — усе працює. Автотести теж пройшли: 510 тестів Jest і перевірки в Chromium/WebKit, зокрема 50 повторних кліків та розмітка 10 тестових записів. У Firefox 132 перевірку блокує наявна в базовій версії помилка `CSS.highlights`. На робочому сервері патч ще не перевірявся, готової production-збірки немає.

Щоб спробувати:

1. Зберегти попередній образ і конфігурацію, щоб можна було відкотитися.
2. В окремій гілці вихідного коду перевірити й застосувати патч. Якщо файл скопійований у корінь репозиторію:

   ```powershell
   git apply --check annotation-shortcuts-v2.8.0.patch
   git apply annotation-shortcuts-v2.8.0.patch
   git diff --check
   ```

   Якщо є конфлікти, потрібно врахувати наші зміни у збірці.
3. Зібрати фронтенд звичним для нас способом (`npm run build`) і спочатку запустити на тестовому сервері.
4. Перевірити на тестових даних: вибрати відповідь мишею → клікнути по фону або тексту → натиснути іншу цифру. Також перевірити введення тексту, меню, збереження та переходи між записами. Після цього можна узгодити встановлення на робочий сервер.

Якщо щось піде не так, повернути попередній образ і конфігурацію. Змін у базі даних цей патч не потребує.

Код і тести є у [гілці на GitHub](https://github.com/FIOWB21/argilla/tree/fix/annotation-shortcuts-click-away). Докладні результати залишив у [PROGRESS.md](./PROGRESS.md), сценарії перевірки — у [TEST_PLAN.md](./TEST_PLAN.md).
