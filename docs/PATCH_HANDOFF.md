# Передача исправления shortcuts администратору

## Результат и состав

При разметке одной записи выбор `1/2/3` переставал работать после клика по фону или обычному тексту. Фокус уходил на BODY, и событие клавиши больше не доходило до контейнера вариантов. Теперь безопасный click-away возвращает фокус последнему активному варианту текущего вопроса. Двойной/тройной клик сохраняет выделение текста и работу цифр. Ввод, поиск, меню, модалки и сочетания с модификаторами защищены guard-условиями.

Пользователь подтвердил работу локального стенда 2026-11-08: «всё работает». Количество ручных попыток не сообщалось. Корпоративная сборка и настоящий backend ещё не проверены.

## Перенос и проверка администратором

1. Установить фактический SHA корпоративного frontend и дополнительные изменения. Одинаковая надпись «2.8.0» не гарантирует одинаковый код. Сохранить исходный образ/digest и параметры сборки для отката.
2. В отдельной ветке корпоративных исходников, из корня репозитория проверить патч, затем применить его. Пример для патча, скопированного в текущий каталог:

   ```powershell
   git apply --check annotation-shortcuts-v2.8.0.patch
   git apply annotation-shortcuts-v2.8.0.patch
   git diff --check
   ```

   Команды не выполнялись в корпоративной среде. На чистой `v2.8.0` применимость проверена через отдельный временный Git index: результат совпал с четырьмя файлами `43e8a1ec`. Обратная проверка на текущем коде также PASS. При конфликтах перенести изменения по diff с учётом корпоративных правок; не заменять весь проект upstream-версией.
3. Перенести относящиеся к исправлению тесты из принятого снимка: [QuestionsForm.spec.js](../argilla-frontend/components/features/annotation/container/questions/QuestionsForm.spec.js), [click-away-annotation-mode.spec.ts](../argilla-frontend/e2e/annotation-mode-page/click-away-annotation-mode.spec.ts) и его [fixture](../argilla-frontend/e2e/annotation-mode-page/click-away.fixture.ts). Очередь для дополнительной проверки — [manual-records.spec.ts](../argilla-frontend/e2e/annotation-mode-page/manual-records.spec.ts) и [manual-records.fixture.ts](../argilla-frontend/e2e/manual/manual-records.fixture.ts). Только рабочий `.patch` этих тестов не содержит.
4. В отдельной рабочей копии без запущенного dev-сервера выполнить принятые в компании установку зависимостей и сборку. Для чистой базы локально использовались Node 20.18.1 и `npm ci --legacy-peer-deps --no-audit --no-fund`; lockfile не менялся. Штатная команда frontend — `npm run build`. Сохранить корпоративные BASE_URL, DIST_FOLDER и параметры backend. Production build/образ в этой работе **NOT RUN / не создан**; ручной стенд запускает `npm run dev`.
5. Поднять staging с синтетическими данными. Пройти [TEST_PLAN.md](./TEST_PLAN.md), включая настоящий путь сохранения, целевой браузер, обычный ввод, открытые меню/диалоги и навигацию. Основной click-away проверять на одной записи. Повторить двойные/тройные клики и 30–50 циклов; фоновый клик сам не должен выбирать или отправлять ответ.
6. Назначить ответственного за внедрение/откат и получить согласование выпуска по [DEPLOYMENT.md](./DEPLOYMENT.md). После выпуска повторить smoke в разрешённом тестовом датасете.

## Откат

Для развёрнутой установки вернуть **предыдущий согласованный образ по сохранённому digest** и прежнюю конфигурацию через CI/CD компании. Проверить вход, открытие записи и штатное сохранение в тестовом датасете. Обновление базы данных патчем не требуется.

Для исходников администратор может создать обратный коммит перенесённого исправления и пересобрать образ. Если накопленный patch применён без последующих изменений этих четырёх файлов, сначала выполнить `git apply --reverse --check annotation-shortcuts-v2.8.0.patch`, затем обратное применение в рабочей ветке и проверить diff. После адаптации под корпоративный код ориентироваться на фактический коммит переноса. Прежний образ компании является точкой отката; публичная `v2.8.0` не заменяет корпоративную baseline.
